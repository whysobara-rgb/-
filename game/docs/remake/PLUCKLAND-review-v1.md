> 원문: `PLUCKLAND-design-v1.md`. 네 관점(재미·설계 / 시장·이름 / 제작 범위·기술 / 내부 모순)을 서로 모르게 따로 평가한 뒤 종합했습니다.
> 점수는 "지금 문서대로 만들었을 때" 기준입니다. 콘셉트 자체의 잠재력은 이보다 높습니다.

## 1. 진짜 강점 (유지)

- **설정이 곧 규칙**(2장 세 가지 법칙): 뿌리가 보이면 뽑힌다, 뽑으면 뭔가 나온다, 옮긴 것은 성질을 지닌다. 보기만 해도 기대가 생기는 구조.
- **뿌리 등급을 색·형태·소리 세 겹으로**(4-1), 글자 없는 거부 피드백 + 지도 자동 표시. "나중에 다시 와야지"를 UI 없이 전달.
- **족쇄(부수지 않음·죽지 않음)**: 바난자와 확실히 갈라지는 무기이고, 5장에서 "집째 옮겨 주기"로 이야기의 해답이 되는 게 문서 전체에서 가장 좋은 장면.
- **0장 배나무 "영차" → 최종장 대말뚝** 감정선. 수집 노력이 업적 팝업이 아니라 합창 소리와 줄 길이로 돌아옴.
- **소원 = 태그·위치 조건**(11장): 실패 없는 가벼운 퍼즐로 마을 꾸미기.
- **행동 지표 기반 검증**(19장): 이전 게임에 없던 규율.
- **데이터 중심 구조**(17장 Pluckable 시트, 고정 태그 조합, 단계별 통과 기준, 축소안 사전 준비).

## 2. 가장 중요한 문제 7가지

### ① 재미의 중심이 "당기기"에 쏠려 있음 (치명)
- 문서의 공력 대부분이 땅속 낚시(5장)에 들어가 있지만, 오래가는 재미는 **옮긴 결과로 세상이 바뀌는 것**에서 나옴(괴혼, 도넛 카운티, 구스 게임).
- 8장 반응은 대부분 **한 번 웃기고 끝나는 개그**(재채기, 사과 맞기, 개미 팻말). 다섯 번째 우체통에서는 죽음. 28종 중 7종은 태그가 없어 뽑아도 시스템상 아무 변화가 없음.
- **수정안**: 반응을 두 층으로. (a) 처음 한 번만 나오는 개그 → 도감에 기록. (b) **매번 작동하는 시스템 규칙** — 집주인은 뽑힌 자기 집을 따라다니며 다시 심을 때까지 투덜댐, 동물은 열에 모임, 주민은 빛·그늘에 모임, 풀어 준 닭은 쑥이를 쫓음 등. 규칙 몇 개만으로 일일이 만들지 않은 놀라움이 생김.

### ② 분량 대비 콘텐츠 밀도가 낮음 (치명)
- 챕터당 기믹 1개 × 약 55~60분. 닌텐도의 소개→응용→비틀기→졸업은 **한 시간 단위가 아니라 5~15분 단위**로 씀.
- 28종 ÷ 330분 = 약 12분에 새 대상 하나. "이것까지 뽑힌다고?" 쇼츠 시리즈를 채우기에도 부족.
- **수정안**: 챕터마다 같은 주제의 **하위 기믹 3개**(2장: 바람 방향 / 상승기류 활공 / 안개 걷기), 10~15분 구역마다 4단계 반복. S·M급 **"곁들이" 대상 60~100개**(반응 1개짜리 데이터 행) + 챕터별 변종(거꾸로 버전, 언 버전). 밀도를 3~5분에 새것 하나로 못 맞추면 **늘리지 말고 메인을 4시간 안팎으로 줄이기**.

### ③ 땅속 낚시의 정체성 위기 (치명)
- "무거운 걸 버텨 이기는 손맛"을 약속하면서, 보정이 겹겹이 쌓여 있음: 보이는 0.15초 / 실제 0.3초 판정, 0.3초 유예, 실패하면 자동 약화(-20%, -40%), 장갑으로 지침 구간 +20%. **실패가 사실상 없으니 승부가 아니라 의식**이 됨. 리듬 5종도 한 번 익히면 끝이고, 결과는 어떻게 당기든 같음.
- **수정안**: 낚시는 "짧고 쫀쫀하고 거의 확실한 의식" + "선택형 실력 층"으로 정리. 실력이 결과에 연결되게: 완벽 훅 → 반짝이는 흙·희귀 변종 확정, 당기기 품질 → 도감 크기 기록, 마지막 "쑥!" 순간 스틱 방향 → 날아가는 방향. 같은 종류를 N번 깔끔하게 뽑으면 **즉시 뽑기**(성장이 괴혼처럼 느껴지게). 숨은 보정 여러 개 대신 **보이는 보조 옵션 하나**.

### ④ 조작: "버튼 2개"는 글자로만 지켜짐 (중대)
- 잡기 한 버튼에 탭 뽑기 / 꾹 낚시 / 입질 재입력 / 누름·뗌으로 텐션 조절 / 떼서 놓기 / 스틱 튕겨 던지기 / 뒤에서 꾹 줄 서기가 다 몰려 있음.
- 구체적 충돌: 떼면 놓아지니 들고 다니는 내내 잡기를 눌러야 하는데, 그러면 같은 엄지로 점프를 못 누름. 무거운 걸 들고 방향을 확 틀면 던지기가 오발됨. **놓을 때 방향을 정하는 입력이 없는데** 바람 원뿔·빛·거울·2장 보스(바람나무를 반대로 심기)는 방향이 필요함.
- **수정안**: 약속을 "**행동 버튼 2개 + 스틱**"으로 다시 쓰기. 들기는 래치(누르면 들고, 다시 누르면 놓기), 던지기는 길게 눌렀다 떼기. 잡기를 **아날로그 트리거(RT/ZR)**로 두면 누르는 깊이가 곧 당기는 힘이라 UI 없이 텐션이 읽힘. 놓는 방향은 쑥이가 바라보는 방향, 미리보기에 방향 화살표 표시.

### ⑤ 범위와 일정이 1인 + AI 체제에 비해 큼 (치명)
- 7개 구역의 진짜 3D 레벨 디자인, 28종 고유 반응, 도깨비 5종, 행렬 AI, 중력 반전 챕터, 마을·소원 15개, 최종장을 9~14개월 차 6개월 안에 넣는 계획. 챕터 하나에 현실적으로 6~7주(회색 박스 1 + 퍼즐 반복·테스트 1.5~2 + 아트 1 + 보스 1~3 + 연결·버그).
- 병목은 코드 속도가 아님. **3D 레벨 디자인, 손맛 튜닝, 플레이 테스트 처리량**이 병목. 이전 게임이 일주일에 15만 줄을 만들고도 "1분 미니게임"이었던 게 증거.
- **문서에 빠진 가장 비싼 결정 두 가지**: (1) **레벨을 어떻게 만들 건지**(웹 스택엔 에디터가 없음), (2) **엔진·플랫폼**.
- **수정안**: 출시 범위 **0장 + 1장(무게) + 2장(바람) + 3·4장 합본(열·물·증기, 중력 반전은 매달린 물체 정도로 축소) + 5장(말뚝도시, 이야기의 핵심) + 최종장**, 메인 4~4.5시간. 중력 반전 챕터를 5장보다 먼저 자르기. 세계를 **1m 타일 격자 + 0.5m 단위 높이**(캡틴 토드식 디오라마)로 제한하고 레벨을 텍스트/JSON으로 작성 + 자동 미리보기·풀이 가능성 검사 봇.

### ⑥ 플랫폼: 지금 기술(웹 + Electron)로는 닌텐도 스위치에 못 감 (치명, 사업)
- 닌텐도 감성 아늑한 어드벤처는 스위치가 스팀만큼 혹은 그 이상 큰 시장인 경우가 많은데, Electron은 콘솔에 못 올림(네이티브로 다시 써야 함).
- **수정안**: 3주 손맛 검증은 지금 웹 스택으로(재사용 극대화, 질문은 기술이 아니라 디자인). **6주 차까지 엔진 결정**: 콘솔이 확정 목표면 Unity(로컬에 설치돼 있음), 스팀 전용이면 웹 유지(기존 코드 40~50% 재사용).

### ⑦ 규칙끼리 부딪히는 곳 (구조적인 것만)
| 충돌 | 내용 | 정리안 |
|---|---|---|
| 앞발 단계 vs 챕터 내용 | M급은 "1장", 도깨비를 풀어야 앞발이 오름. 그런데 0장에서 우물(M)을, 1장 도깨비 전에 둥근 바위를, 2장에서 여관(L) 행렬을 해야 함 | 단위를 "앞발 단계 0~5"로 통일, S=0·M=1·L=2·XL=4. 1단계는 0장 배나무 뽑기 보상으로. 도깨비 풀어 주기 당기기는 앞발 제한 면제 |
| 0장 튜토리얼이 틀린 규칙을 가르침 | 배나무는 "무지개 결(줄 서기 전용)"인데 0장 비틀기는 "은빛 배나무가 안 뽑힘". 은빛 = L급이라 "은빛 = 마을 전체가 필요"로 잘못 배움 | 배나무는 무지개로 통일. 앞발 거부도 가르치고 싶으면 0장에 은빛 집을 따로 두고 2장에 돌아와 뽑게 |
| 4-3 "뿌리 보이면 무조건 뽑힘" vs 잠금 상태들 | 앞발 부족, 쇠말뚝, 도깨비 고집, 혼자일 때 배나무 = 뿌리 보이는데 안 뽑힘. 빛 태그가 "숨은 뿌리를 드러냄" = 뿌리 안 보이는데 뽑힘 | "영원히 안 뽑히는 건 없다. 일시 거부는 네 가지 읽히는 잠금(앞발·말뚝·도깨비 눈·무지개) 중 하나"로 다시 쓰기. 배경 소품용 "붙박이 장식" 분류 추가 |
| 행렬 길 만들기 퍼즐 vs 0.5초 텔레포트 | 막히면 텔레포트 → 퍼즐을 건너뜀. 정해진 경로 노드는 플레이어가 만든 길을 못 따라감 | 지형 때문에 막히면 대기 지점에서 멈추고 주민이 장애물을 가리킴. AI 오류일 때만 이미 유효한 노드로 텔레포트. 다리·둑을 놓으면 경로 그래프가 갱신되게 |
| 저장 vs 재생 법칙 vs 태그 퍼즐 | 저장은 "뽑힘 여부"만, 그런데 퍼즐은 "어디에 옮겨 놨는지"가 핵심. "시간 지나면 원래대로"가 열린 물길·동굴까지 되돌리는지 불명 | 구역별로 옮긴 물체의 위치·방향·상태 전부 저장(몇십 개라 가벼움). 재생은 구멍만 메우고(내용물을 가져간 뒤), 옮긴 물체·열린 길은 그대로. 그루터기는 배치만 리셋 |
| "무작위 없음" vs 가끔 큰 순무·10회 보장 | 보장 천장은 확률 뽑기에서 쓰는 개념 | "입력과 저항은 결정적, 보상은 설계된다"로 범위 지정. 보장 천장 삭제, 큰 순무는 물 태그 범위 안이면 항상 크게(태그 교육도 됨), 크기 기록은 당기기 실력의 결과로 |
| 부수지 않음 vs "뚝!"·약해지는 뿌리·내려앉는 바닥 | 실패음 "뚝!", "뿌리가 약해진다"는 손상처럼 읽힘 | 실패는 "쭉~ 미끄러져 엉덩방아", 문구는 "뿌리가 약해짐"이 아니라 "손이 익었다". 바닥은 "내려앉음"이 아니라 "한 층 아래로 가라앉음(다시 뽑을 수 있음)" |
| 캡슐 그림이 규칙상 불가능 | "쑥이가 여관을 들어 올림"인데 L급 이상은 혼자 못 듦 | "쑥!" 순간 1초간 머리 위로 들어 올리는 포즈를 넣고 바로 주민들에게 넘기기 → 캡슐이 진실이 됨 |

그 밖에: 태그 6×6 조합표 전체를 명시(정의 안 된 조합은 "반응 없음"으로), 태그 범위를 미터 대신 격자 칸으로, 위치형 소원(바다 쪽·가장 높은 곳)은 지형에 상관없는 관계 조건으로 + 한 번 이루면 영구, S급은 누르는 길이가 아니라 등급으로 분기하고 "피라미" 유형 삭제, 최종장 난이도는 줄 길이에 따라 바뀌지 않게 고정(줄 길이는 연출만), 점프 높이·헤엄·추락 규칙 같은 이동 사양 추가.

## 3. 시장·이름

- **PLUCKLAND**: 스팀·itch.io·앱스토어 웹 검색에서 겹치는 게임은 못 찾음. 다만 이 환경에서는 공식 상표 데이터베이스(USPTO·EUIPO·KIPRIS) 직접 조회가 막혀 있어서, 출시 전 정식 조회가 필요함. 영어 "pluck"은 깃털·눈썹처럼 **작은 것을 뽑는 느낌**이라, "집째 뽑는" 판타지와 어긋남 → "uproot / move" 계열 이름 3~5개를 캡슐 시안으로 A/B 테스트 추천.
- **바난자 대응**: 동키콩 바난자는 2025년 7월에 나온 닌텐도 대작(검색 기준 높은 평점과 큰 판매량)이고 스팀에는 없음. 공개 포지셔닝을 "바난자와 다르다"로 잡으면 오히려 비교를 불러옴 → **"가족이 안에 탄 집째로 뽑아 이사 가기"**처럼 바난자가 못 하는 판타지를 앞세우기. 비교는 내부 점검용으로만.
- **마케팅 영상 규칙**: 당기기 텐션 장면은 클립당 1초 이하. 영상마다 "준비 → 뭐가 딸려 나오는지 → 세상이 어떻게 바뀌는지". 당기기 게이지를 오래 보여 주면 다시 "미니게임 모음"으로 읽힘.
- **숫자 관문 추가**: 넥스트 페스트 전 위시리스트 약 7천, 이후 2만+, 출시 목표 3~5만. 12개월 차에 1만 미만이면 범위 축소나 연기. 데모는 넥스트 페스트 1~2달 전에 공개.
- **가격**: $14.99 + 출시 할인 10~15%, 지역별 가격. $19.99는 풀 버전에 데모 전환율이 좋을 때만.
- **주인공**: "너구리"는 영어로 tanuki(너구리)인데 묘사는 raccoon(라쿤). 해외에선 다른 동물이고 라쿤은 인디 마스코트로 흔함 → 도깨비·한국 설화와 어울리고 해외에서 더 눈에 띄는 **너구리(tanuki)로 갈지 의식적으로 결정**. 큰 앞발을 기억에 남는 실루엣으로.
- **예상 매출(스팀 첫해, $14.99 기준 추정)**: 잘 해낸 경우 약 1.2만~4만 장(순수익 약 7.5만~24만 달러, 1억~3.3억 원대). 처음 내는 1인 스튜디오의 흔한 결과는 1.5천~5천 장(순수익 약 0.9만~3만 달러). 위시리스트를 얼마나 모으느냐가 가장 큰 변수.

## 4. 기존 코드에서 살릴 수 있는 것 (약 40~50%)

- **그대로/조금 고쳐서**: 뽑기 연출(끙차·뿌리 뜯김·팡!·흙 터짐), 너구리 리그·표정, 절차적 모델 도구(지오메트리·재질·외곽선·팔레트), 가림 처리(occlusion), 사운드 엔진 전체(dsp·믹서·시퀀서·자막·목소리), UI 프레임워크, 저장(버전 이전 패턴), 입력(키보드·패드·2~4인), Electron·스팀 패키징, 테스트·도구 문화.
- **새로 만들어야 함**: 높이와 점프가 있는 이동, 탐험 카메라(높이 대응), 레벨 작성 방식, 행렬, 소원 그림말, 도깨비 상태 기계, 수백 개 사물을 감당할 렌더링(인스턴싱).
- 옛 저장소를 그대로 고쳐 쓰면 경찰·점수·봇·대회 같은 죽은 시스템이 딸려 옴 → **새 프로젝트를 만들고 1주 정도 들여 재사용 패키지를 뽑아 옮기기** 추천.
- 결정성(60Hz 동기)은 온라인 대전용이라 1인 게임엔 필요 없지만, **고정 시간 단계 + 입력 기록**은 유지(낚시 판정이 프레임레이트에 흔들리지 않게, 버그 재현·자동 풀이 테스트용).
- 퍼즐 물리는 **강체 물리 대신 정해진 결과**로: 바위는 격자 따라 한 칸씩 구르고, 던지기는 고정 포물선으로 자석 착지, 탄성은 정해진 높이로. "왜 이렇게 됐지?"를 막고 "절대 배신하지 않는다"를 지킴.

## 5. 추천 다음 단계

1. **기획서 v1.1**: 위의 치명·구조적 항목(①~⑦)을 반영. 특히 앞발 단계, 0장 배나무, 4-3 재작성, 저장·재생, 조작 계약(래치·트리거·방향), 무작위 범위, 범위 축소(4~4.5시간).
2. **3주 손맛 검증(웹 스택, 기존 코드 재사용)**:
   - 1주: 작은 격자 회색 박스(높이 2단 + 경사)에서 새 이동 컨트롤러 + 기존 너구리·입력·카메라. 잡기 탭/홀드, 잉어·메기 곡선 낚시, 기존 뽑기 연출 연결.
   - 2주: 대상 8~12개(곁들이 포함), 놓기 미리보기·방향, 태그 2~3개, 시스템 규칙 2개(집주인 따라오기, 동물이 열에 모이기).
   - 3주: 처음 해 보는 사람 5명 테스트. 관문 2개만: "시키지 않아도 옆 대상을 또 잡는가", "실패했을 때 '내가 못했다'고 느끼는가".
3. **6주 차 엔진 결정**: 콘솔이 확정 목표면 Unity, 아니면 웹 유지.
4. **수직 슬라이스 정의**: "0장 + 1장 절반"이 아니라 **"반복되는 모든 콘텐츠 종류를 최종 품질로 하나씩"**(대상 12~15개 5칸 전부, 구멍 프리팹 2종, 태그 3종, 도깨비 1종, 행렬 1회, 소원 2개, 줄 서기 1회). 여기서 콘텐츠 종류별 제작 시간을 재서 전체 일정을 다시 잡기.
