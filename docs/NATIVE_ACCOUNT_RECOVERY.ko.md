# 네이티브 이메일 인증·비밀번호 재설정 연결

2026-09-16. 기준 앱 5867f37, 서버 런타임 계약 38cacbdd / PR 문서 9be81a0. 체크리스트 10번 모바일 API 연결 공백의 부분 작업이다. 출시 점수 44/100을 유지한다.

## 구현 경로

로그인 → 비밀번호를 잊으셨나요? → 공개 capabilities 조회 → 이메일 입력 → 재설정 메일 요청.
마이 → 이메일 인증 → 현재 로그인 계정의 /account/email 상태 조회 → 인증 메일 요청.
서버 설정과 같은 공개 AUTH_PUBLIC_WEB_ORIGIN을 지정한 앱에서는 메일 링크를 직접 붙여넣고 목적/주소를 검사한 뒤, 확인창을 거쳐 재설정 또는 인증 완료 요청을 보낼 수 있다.

실제 API: GET /auth/recovery/capabilities; POST /auth/recovery/request, /auth/recovery/reset, /auth/recovery/verify; GET /account/email; POST /account/email/request.

기존 서버가 보내는 링크는 HTTPS_ORIGIN/#auth-reset/64자리hex 또는 #auth-verify/64자리hex다. 앱은 신뢰 주소를 링크에서 추론하지 않는다. 공개 빌드 설정 AUTH_PUBLIC_WEB_ORIGIN이 없거나 올바르지 않으면 붙여넣기/소비 기능은 비활성이다. 링크를 열거나 자동으로 클립보드에서 읽지 않고 문자열을 검증해 토큰만 고정 API의 JSON 본문으로 보낸다. 공개 메일 주소 설정은 비밀 키가 아니며 서버의 AUTH_PUBLIC_WEB_ORIGIN과 일치해야 한다. 이번에 현재 배포 빌드/서버 설정에 값을 넣지 않았다.

## 보안·오류 원칙

공개 복구 요청은 저장된 JWT를 읽지도 보내지도 않지만 로그인 세대가 바뀌면 전송/응답을 중단한다. 인증 메일 요청과 현재 계정의 상태 조회는 기존 JWT가 필요하다. 이전 구매/환불 경로의 세션 보호와 멱등키 동작을 유지한다. 민감 요청은 리다이렉트를 따르지 않고 자동 재전송하지 않는다.

메일 요청의 accepted 응답은 계정 존재·실제 발송·메일 도착의 증거가 아니다. 고정된 조건부 안내를 사용하며 임의 서버 문구를 출력하지 않는다. 로컬 60초 재요청 대기는 UX 보호일 뿐 서버 제한을 대신하지 않는다.

비밀번호는 서버와 동일한 입력 기준을 재사용한다. 링크·새 비밀번호는 영구저장/저널/분석 로그/라우트 인자에 넣지 않고 전송 전·백그라운드·계정 변경·dispose 시 컨트롤러를 지운다. 메모리 완전 소거나 OS 앱 전환 미리보기 차단을 주장하지 않는다. 이미 전송된 요청은 이후 로컬 로그아웃으로 취소할 수 없다.

메일 토큰의 만료·일회성·권한은 기존 서버 구현이 결정한다. 인증 링크의 계정과 로그인 계정이 다를 수 있어 verified 응답만으로 현재 계정을 인증 완료 표시하지 않고 /account/email을 다시 조회한다. 재설정 후 자동 로그인하거나 로컬에서 새 JWT를 만들지 않는다. 불명확한 완료 응답에는 성공/실패를 단정하지 않고 재로그인/상태 조회를 안내한다.

## 검증과 제외 범위

전용 CI는 모의 HTTP·메모리 토큰 저장소·Flutter 위젯 검사다. 공개/보호 API의 인증 헤더 구분, 링크 목적·origin 검증, 오류/계정 변경/백그라운드/중복 탭, 작은 화면·글자 확대, 실제 로그인 화면 진입점을 검사한다. 실제 Resend 메일 발송/수신, 사용자의 실계정 비밀번호 변경, 실 토큰 소비는 수행하지 않는다.

Android App Links/iOS Universal Links로 메일 클릭 후 앱을 자동 실행하는 연결은 이번 범위가 아니다. 승인된 도메인 소유 확인과 앱 서명 설정 후 별도 검수한다. 수동 붙여넣기는 그 연결의 대체 인수 증거가 아니다. 실제 서버 배포·전체 계정 탈퇴/보존·본인/연령 인증·PG·스토어는 남는다. 서버 DB/키/거래 게이트는 변경하지 않는다.

참고: Flutter 공식 form validation, OWASP Forgot Password Cheat Sheet. 실제 증거는 커밋별 CI 산출물과 확인한 실행 상태로 구분한다.
