## API와 의미

GET /account/capabilities 및 /account/closure-check로 현재 GP·미개봉/환불대기·보관/배송 상품·진행 배송/결제/환불/문의 수량을 표시한다. 항목은 중복될 수 있고 합산해서 미처리 총건수 또는 탈퇴 적격 여부로 판단하지 않는다.

현재 비밀번호·사유·정확한 '탈퇴 요청' 문구 → 최종 확인 → POST /account/closure-requests와 Idempotency-Key. 접수는 계정 삭제나 처리기한 확약이 아니다. 고객에게 보유 권리 포기를 요구하거나 현황이 0이어야만 접수할 수 있도록 추가 제한하지 않는다.

GET /account/closure-requests/by-request/:key로 응답 유실/재시작 결과를 조회한다. 취소는 POST /account/closure-requests/:id/cancel. 새 GET /account/closure-requests/:id로 취소 결과를 쓰기 없이 확인한다. 이 GET은 새 서버 커밋 반영이 필요하며, 구서버의 404를 취소/삭제 성공으로 취급하지 않는다.

## 복구·세션 경계

기존 보안 저장소 어댑터를 사용해 계정·서버별 요청번호·종류·정규화 사유만 저장한다. 비밀번호·JWT는 저장 구조에 넣지 않는다. 재시도 시 현재 비밀번호를 다시 입력하고 같은 요청번호/사유를 사용한다. 인증·통신·응답 오류에서 자동 POST 재전송이나 요청 기록 삭제를 하지 않는다. 결과 조회를 먼저 하고 사용자가 최종 확인할 때 서버 영수증을 다시 대조한 뒤 로컬 기록을 지운다. 저장소 삭제 실패는 새 요청 발급 사유가 아니다.

현재 로그인 세대를 전송 전후 확인하며 로그인 변경 시 화면 데이터를 정리한다. 확인창 중 로그아웃·백그라운드 전환은 아직 전송하지 않은 동작을 중단한다. 이미 전송된 동작을 로컬 로그아웃으로 되돌릴 수 있다는 뜻은 아니다. 입력 컨트롤러 정리를 메모리 완전 소거나 OS 화면 미리보기 보호라고 표현하지 않는다.
