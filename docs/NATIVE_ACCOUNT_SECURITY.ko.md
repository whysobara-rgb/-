# 네이티브 계정 보안 연결 · 출시 체크리스트 10번의 부분 작업

2026-09-16. 앱 기준 ddb9b211, 서버 계약 기준 38cacbdd. 기존 마이 화면에 계정 보안 진입점을 연결한다. 관리자 MFA 화면·PortOne·실 PG·원본 DB 변경·실제 서버 배포·상용 서명은 이번 범위가 아니다.

## 연결한 실제 경로

마이 → 계정 보안 → GET /account/capabilities로 ACCOUNT_SUPPORT_V1 확인.
현재 비밀번호·새 비밀번호·확인 입력 → 사용자 확인 → POST /account/password.
현재 비밀번호 입력 → 사용자 확인 → POST /account/revoke-sessions.
서버의 changed/revoked=true와 reauthenticate=true를 확인한 뒤 해당 로그인 세대만 로컬 로그아웃한다. 모든 원격 세션의 회수는 서버 auth_version 변경에 의존한다. 앱이 서버 회수를 대신하지 않는다.

현재/신규 비밀번호는 자동으로 공백을 제거하지 않는다. 새 비밀번호 검사에 서버의 영문·숫자, 8~64자, UTF-8 72바이트 상한을 반영한다. 비밀번호는 요청 본문 이외의 저장소·로그·라우트 인자·재시도 저널에 넣지 않는다. 입력 컨트롤러는 전송 전, 계정 변경·화면 종료·백그라운드 전환 시 정리한다. 메모리의 암호학적 완전 삭제나 OS 화면 미리보기 차단을 주장하지 않는다.

## 계정 경계와 응답 유실

AuthProvider의 비밀정보 없는 sessionGeneration으로 같은 사용자 재로그인도 구분한다. ApiClient의 신규 getForSession/postForSession은 비동기 토큰 읽기 전후와 응답 수신 후 로그인 세대를 재검사한다. 자격증명 헤더가 없는 요청은 보내지 않고 redirect는 따르지 않는다. 이전 계정의 응답으로 새 계정의 로그인정보를 지우지 않는다. 이미 발송된 요청을 나중의 로그아웃으로 되돌릴 수 있다는 의미는 아니다.

네트워크 실패·확인되지 않은 응답에는 비밀번호 변경을 자동 재전송하지 않는다. 서버 성공/실패를 단정하지 않고 현재 기기의 해당 세션을 정리해 재로그인 확인을 안내한다. 확정 거절(400/403/409/429)은 고정 안내문을 표시한다. 서버의 임의 오류문·입력값을 그대로 화면에 출력하지 않는다. 기존 거래 API·운영 기능 플래그는 변경하지 않는다.

## 검증 계획과 남은 범위

저장소/인증 경계 테스트: 전송 전 로그인 변경, 토큰 읽기 지연, 익명 요청, 늦은 응답, redirect, 무재시도, 비밀번호 검사, 원문 보존, 정확한 결과 플래그, 같은 사용자 재로그인.
위젯 테스트: 마스킹, 불일치·취소, 정상 변경/전체 세션 해제, 미확정 결과, 서버 미배포/비활성, 백그라운드 정리, 로그인 변경 경쟁, 작은 화면과 2.5배 글자 확대.
실제 운영 계정·Android/iPhone 기기·네이티브 인증키 삭제·서버 배포 검수는 별도다. 화면 추가만으로 9번 전체 접근성 또는 10번 모든 모바일 계약 공백을 DONE으로 바꾸지 않는다. 이메일 인증/재설정, 탈퇴 요청/보존, 카드 결제/환불, 나머지 모바일 API 전수 대조는 남아 있다.
