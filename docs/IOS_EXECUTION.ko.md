# iOS 검증과 배포 구분

워크플로: `.github/workflows/ios.yml` (macOS, Flutter 3.35.4).

1. CocoaPods 설정과 잠금된 Flutter 의존성으로 시뮬레이터 앱을 빌드합니다.
2. `lib/main.dart` 앱을 설치·실행하고 첫 Flutter 프레임과 화면 캡처를 확인합니다.
3. 별도 CI 진입점으로 실제 Keychain에 처리 미확정 거래를 저장합니다.
4. 프로세스를 종료·재시작하여 같은 구매 키로 복구하고 개봉은 GET 재조회만 수행하는지 확인합니다.

테스트 거래 HTTP는 모의 응답이며 Render나 PG에 금액 변경 요청을 보내지 않습니다. 배포할 앱은 `lib/main.dart` 진입점으로 만든 것만 사용합니다.

첫 실행에서 시뮬레이터 설치가 60초를 초과해 실패했습니다. 시뮬레이터를 빌드 전에 준비하고 설치 제한시간을 240초로 조정했으며, 기기 및 실행 명령 진단 기록을 보관합니다. 실패를 성공으로 취급하거나 검사를 생략하지 않습니다.

산출물 `ios-simulator-app`은 Mac 시뮬레이터용입니다. 실제 iPhone/TestFlight용 IPA가 아니며 운영 서명이 없습니다. 최종 실행 결과는 해당 커밋의 Actions 기록으로 판단합니다.

Apple 계정, 팀 ID, 서명/프로비저닝, 실기기 및 앱 등록은 별도 출시 조건입니다. 현재 사용 중인 iOS Bundle ID를 임의로 바꾸지 않았습니다.

설치 이후의 첫 화면 신호는 iOS 통합 로그에서 읽어야 하므로, Flutter 자체 시뮬레이터 로그 리더와 같이 `log stream`을 수집하도록 보완했습니다. 일반 stdout만으로 성공/실패를 판단하지 않고 실패 화면도 저장합니다.
