# 앱 거래 연결: 4단계

## 반영 범위

GP 상품 상세의 구매 버튼에서 새 확률 확인 화면으로 이동한다. 정확한 고정 확률, 일반/프리미엄 분류, 상품별 전환 GP를 확인하고 동의한 뒤 구매한다. 완료 화면은 미개봉 보관함으로 안내하며 자동 개봉하지 않는다. 상품 보관함 상단의 미개봉 캡슐 버튼으로 다시 진입할 수 있다.

미개봉 목록은 20개씩 페이지를 이동하고, 캡슐 선택 시 원주문 상품명을 확인한다. 개봉 전 명시적 확인을 거쳐 서버 결과만 표시한다. 결과 확인 후 돌아오거나 미개봉 목록으로 이동할 수 있다. 보관함 탭 재진입 시 상품을 서버에서 새로 조회한다.

기존 라인업의 상대 weight 기반 확률 표시는 제거했다. 실제 고정 확률은 구매 확인 화면의 /gachas/:id/odds 응답으로 표시한다.

## 재시작·실패 복구

- UUID v4 구매 키와 원본문을 기기 보안 저장소에 기록한 후 전송한다. 저장 실패 시 구매하지 않는다.
- 계정 ID와 API 서버별 복구 기록을 분리하고 로그인 당시 토큰에 세션을 고정한다. 변경 요청 전 서버의 본인 ID를 확인한다.
- 통신 실패, 해석 불가 응답, 5xx, 401, 503, 원인이 확인되지 않은 충돌은 기록을 유지한다. 새 구매를 막고 같은 키·본문으로 복구한다.
- 서버의 명시적 미차감 거절은 기록을 해제해 새로운 조건을 확인할 수 있다. 가격·확률·재고 거절은 백엔드 오류의 ORDER_REJECTED 표식으로 구분한다. 이전 서버의 표식 없는409는 보수적으로 유지한다.
- 캡슐 UUID를 개봉 전에 저장하고 응답이 없어도 GET 결과 확인부터 제공한다. 서버가 아직 미개봉이라고 확인한 경우에만 같은 캡슐 개봉 재요청 버튼을 표시한다.
- 결과를 사용자가 확인할 때까지 개봉 복구 기록을 유지한다. 다른 캡슐의 개봉은 이전 결과를 확인한 뒤 가능하다.
- 구매 영수증의 과거 잔액을 현재 잔액처럼 덮어쓰지 않는다. /users/me로 갱신하고 PostgreSQL bigint 문자열 잔액을 정수로 해석한다.

## 실행 조건

```sh
flutter run --dart-define=API_BASE_URL=https://YOUR_TEST_API \
  --dart-define=ENABLE_GP_ORDER_PREVIEW=true
```

새 주문·개봉 백엔드 마이그레이션 적용과 개발/테스트용 GP·명시적 확률 설정이 선행해야 한다. ENABLE_LEGACY_TRANSACTIONS와 동시에 켜지 않는다. release 빌드에서는 플래그와 무관하게 새 변경 요청이 차단된다.

이번 단계는 API 계약·화면·실패 복구 연결이며 실제 기기에서 PG 결제까지 완료한 출시 검증은 아니다. 새 AAB, 실서버 배포, OAuth/다날·환불·GP 전환을 완료한 것으로 표시하지 않는다. 관리자 확률 운영과 실제 기기 검증이 남아 있다.

## 검증

모의 HTTP와 메모리 저장소를 이용한 거래 계약·복구 테스트, 화면 동의/미개봉 지급 흐름, 좁은 화면·확대 글자 레이아웃 검사를 CI에서 실행한다. 실제 Android/iOS 보안 저장소, 실행 중 OS 종료, 기기 네트워크 전환은 별도 실기기 검증이 필요하다.
