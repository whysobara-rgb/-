# 네이티브 GP 전환·복구 · 2026-09-15

보관함에서 잠금 해제된 보관 상품 1~100개 선택 → 서버 전환 견적 → 조건 동의 → 전환 → 내역 → 복구 확인 → 서버 복구를 연결했다. 마이와 보관함에서 전환 내역을 열 수 있다.

서버 금액·정책·상품 ID·합계를 검증한다. 앱이 전환율이나 잔액을 확정하지 않으며 처리 후 프로필을 다시 조회한다. 잠긴 상품을 조용히 제외하지 않고 선택을 수정하도록 안내한다. 전환 완료 상품은 보관함에서 전환 완료로 표시되고 배송·재전환할 수 없다.

계정과 서버별 보안 저장소에 최초 변경 요청 전에 요청 번호/선택 ID/금액/견적 버전을 기록한다. 저장 실패면 요청을 보내지 않는다. 중복 터치는 계정별로 직렬화하며, 응답 유실·형식 불일치·인증/서버 오류는 복구 기록을 남긴다. 재접속 시 전환은 GET /inventory-conversions/requests/:key, 복구는 GET /inventory-conversions/:id로 먼저 확인한다. 사용자가 이어서 확인을 선택하면 기존 요청 번호와 본문으로 재시도한다. 성공 영수증을 확인해야 기록을 지운다.

원자적 서버에서 확정 거절(검증/상품 미존재/상태 충돌)을 받으면 해당 요청 기록을 해제하고 새 견적을 받게 한다. 기존 성공 요청을 재전송하면 서버가 최초 영수증을 돌려준다. 실제 출시 전 느린 요청·연결 장애를 포함한 실서버 통합 검수는 별도로 필요하다.

## 활성화·검증 범위

Android/iOS 검증 빌드에 ENABLE_GP_CONVERSION_PREVIEW=true를 지정했다. release 빌드와 legacy 거래 설정에서는 계속 차단된다. 서버에도 전환 활성화/정책 설정이 필요하며, 신규 요청 복구 경로는 서버 PR #3의 후속 변경이다. 운영 DB나 실결제를 변경하지 않는다.

8개 신규 단위·위젯 검사는 선택/금액/정책 검증, 저장 실패, 응답 유실 후 조회, 동일 키 재시도, 계정·서버 분리, 중복 실행, 서버 복구 제한, 선택·동의·전환·내역·복구 UI 흐름을 다룬다. 실행 결과는 현재 커밋의 CI 기록을 기준으로 확인한다.

## 남은 네이티브 연결

배송 견적·신청·취소, 다날 결제·부분 환불·대사, 계정 복구·본인확인·문의·알림, 최신 홈과 웹 영상의 통합, Android/iPhone 실기기 검수. 이번 변경은 영상 수정이나 출시 완료본이 아니다.
